# 02 系统总体架构

## 1. 架构总览

系统采用**前后端分离 + AI 服务独立部署**的三服务架构, 在保证工程简洁性的同时将"业务系统"与"AI 能力"解耦:

```
┌────────────────────────────────────────────────────────────┐
│                      浏览器(用户)                          │
│      Vue3 + TypeScript + Element Plus + Pinia + ECharts    │
└──────────────┬─────────────────────────────────────────────┘
               │ HTTP/JSON (Bearer JWT, REST /api/*)
               ▼
┌────────────────────────────────────────────────────────────┐
│              backend (Spring Boot 3, :8080)                │
│  认证鉴权(JWT 拦截器) │ 业务模块 │ MyBatis-Plus │ MySQL     │
│  用户/知识库/文档/会话/统计/评估/配置                         │
└──────┬──────────────────────────┬──────────────────────────┘
       │ JDBC                     │ HTTP + X-Internal-Token
       ▼                          ▼
┌──────────────┐        ┌─────────────────────────────────────┐
│ MySQL 8 (:3306)│       │      rag-service (FastAPI, :8000)   │
│  13 张业务表   │       │ 文档解析→清洗→分块→向量化→Chroma     │
└──────────────┘        │ 检索→重排→上下文→LLM 生成            │
                        │ ┌───────┐ ┌───────┐ ┌─────────────┐ │
                        │ │Chroma │ │BGE/   │ │LLM(OpenAI   │ │
                        │ │向量库 │ │Embed  │ │Compatible)  │ │
                        │ └───────┘ └───────┘ └─────────────┘ │
                        └─────────────────────────────────────┘
```

- **frontend(Vue3)**: 纯静态部署, 通过 Nginx 反代 `/api` 到后端, 不接触任何密钥;
- **backend(Spring Boot)**: 业务中枢, 负责认证、授权、业务数据、异步任务编排, 自身不做向量化与生成;
- **rag-service(FastAPI)**: AI 能力中枢, 持有 Embedding/LLM/Chroma, 对外仅暴露 `/api/*` 内部接口(令牌校验)与 `/health`。

## 2. 关键设计决策

### 2.1 为什么独立 RAG 服务(而非嵌入 Java)

1. **生态适配**: BGE 向量模型、LangChain 分块器、Chroma 客户端均为 Python 生态, 强行嵌入 Java 需引入 JNI/HTTP 桥接, 复杂度反而更高;
2. **资源隔离**: 模型加载内存占用大(数百 MB 起), 独立进程避免拖垮业务服务;
3. **独立伸缩**: 重推理场景可单独扩容 rag-service 副本, 业务层不受影响;
4. **故障隔离**: 模型/向量库故障不阻塞登录、管理等纯业务功能。

同时刻意避免过度设计: 仅两个后端服务 + 一个数据库, 不引入注册中心、消息队列、网关——异步任务用线程池 + 数据库状态机即可满足课题规模。

### 2.2 内部通信安全

- Java → Python 全部请求携带 `X-Internal-Token`(环境变量注入, 两端一致);
- rag-service 的 `/api/*` 路由统一挂 `verify_internal_token` 依赖, 令牌不匹配返回 401;
- `/health` 公开(仅返回存活状态, 无敏感信息)。

### 2.3 配置与密钥管理

- 单一 `.env` 文件驱动全部服务(见 `.env.example`), 密钥只经环境变量进入进程;
- Python 侧 `pydantic-settings` 读取; Java 侧 Spring 环境注入(`APP_JWT_SECRET`、`APP_RAG_INTERNAL_TOKEN` 等);
- 日志层 `SensitiveFilter` 对 `sk-*`、`Bearer *`、`api_key` 模式打码; `/api/config` 运行时信息接口不返回密钥字段; 前端无任何密钥。

## 3. 数据流

### 3.1 文档入库(离线)

```
管理员上传 → backend 校验(白名单/大小/随机名/防穿越) → 落盘 + 状态 PENDING
  → 异步线程池: 状态 PARSING → 调 rag-service /api/ingest/file
      → 解析(pypdf/python-docx, 保留页码) → 清洗(控制字符/NFKC/装饰线/页码行)
      → 分块(LangChain RecursiveCharacterTextSplitter, 中文分隔符, chunk_index 全局编号)
      → 向量化(BGE, 批量) → 写入 Chroma 集合 kb_{kb_id}(带完整元数据)
  → 返回 chunk_count → backend 状态 COMPLETED(失败则 FAILED + error_message)
```

### 3.2 在线问答

```
用户提问 → backend: 会话定位/创建 → 保存用户消息 → 取历史窗口(默认6轮)
  → 组装 ChatRequest(RagConfig 全局参数 + 请求级覆盖)
  → rag-service /api/chat/query
      → preprocess_query → embed_query → Chroma Top-K(可选 CrossEncoder 重排)
      → build_context(编号 [1][2]... 含页码) → Prompt(系统提示+历史+当前问题)
      → LLM 生成 → {answer, sources[], retrievalTime, generationTime}
  → backend: 保存助手消息(sources JSON) + qa_record → 返回前端渲染
  → 前端: 渲染 Markdown 风格回答, 引用 [n] 可展开查看原文片段/相似度/页码
```

### 3.3 评估实验

```
管理员发起评估任务(模式/参数/数据集) → backend 异步执行
  → 逐题调用 rag-service /api/evaluation/batch(真实运行, 单题失败记录并继续)
  → rag-service 计算逐题指标(retrieval_hit/precision/recall/keyword/citation/耗时)
  → backend 持久化 evaluation_result + 任务级 metrics JSON → COMPLETED
  → 前端: 明细抽屉 + 人工评分(1-5 分/幻觉标记) + 任务对比 + CSV 导出
```

## 4. 技术栈清单(实际采用)

| 层 | 技术 | 版本 | 用途 |
|----|------|------|------|
| 前端 | Vue / Vite / TypeScript | 3.5 / 6.0 / 5.6 | SPA 框架/构建/类型 |
| 前端 | Element Plus / Pinia / Vue Router / ECharts / Axios | 2.9 / 2.3 / 4.5 / 5.6 / 1.7 | 组件库/状态/路由/图表/请求 |
| 后端 | Spring Boot / Java | 3.5.4 / 21 | 业务服务 |
| 后端 | MyBatis-Plus | 3.5.7 | ORM(逻辑删除/分页/LambdaWrapper) |
| 后端 | jjwt / spring-security-crypto / springdoc | 0.12.6 / - / 2.8.5 | JWT / BCrypt / OpenAPI 文档 |
| RAG | FastAPI / Pydantic v2 / Uvicorn | - | AI 服务框架 |
| RAG | LangChain(text-splitters) | - | RecursiveCharacterTextSplitter 分块(唯一引入的 LangChain 组件) |
| RAG | sentence-transformers (BGE) | - | 本地向量模型(bge-m3, 可切 bge-small-zh-v1.5 或 OpenAI 兼容 API) |
| RAG | Chroma | - | 向量数据库(HNSW, cosine, 每知识库一集合) |
| RAG | pypdf / python-docx | - | 文档解析(保留页码) |
| 存储 | MySQL | 8.4 | 业务数据(13 张表) |

```
│   └── app/
│       ├── core/        # config / logging(脱敏) / errors

│       ├── llm/         # base + openai_compatible + factory
│       ├── vectorstore/ # ChromaStore
│       ├── document/    # parser(白名单/页码) / cleaner
│       ├── rag/         # chunker / retriever / reranker / context_builder / prompts / pipeline
│       ├── evaluation/  # metrics / runner
│       ├── api/         # routes / ingest_service
│       └── tests/       # 53 项离线测试(FakeEmbedding/FakeLLM)

```
