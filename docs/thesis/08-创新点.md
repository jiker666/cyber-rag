# 08 创新点

> 按课题要求, 创新点围绕: 安全领域知识库构建、RAG 问答、回答-来源绑定、LLM_ONLY 与 RAG 对照。以下均为系统已实现内容, 不含未落地设想。

## 创新点 1: 面向网络安全领域的知识库工程化构建

将非结构化安全知识(漏洞原理、防御指南、安全编码规范、法律法规)转化为**可检索、可溯源、可评估**的结构化资产:

1. **领域语料组织**: 知识库按安全子域(Web 安全/Java 安全/API 安全)分库, Chroma 集合级隔离(`kb_{id}`), 检索天然限定在授权范围内——把"访问控制"思想下沉到向量检索层;
2. **页感知分块**: PDF 逐页解析后分块, 每个 chunk 携带 `document_id/document_name/knowledge_base_id/chunk_index/source/page` 完整溯源元数据, 支撑"引用精确到页";
3. **中文优先分块策略**: LangChain RecursiveCharacterTextSplitter 配置中文语义分隔符(。！？；,)优先切分, 相比重构英文分隔符更贴合中文语义边界;
4. **入库质量门禁**: 解析白名单(4 类文档)+ 清洗规则(控制字符/NFKC/装饰线/页码行)+ 参数校验, 从源头抑制噪声进入向量库。

## 创新点 2: 回答-来源强绑定的可信问答机制

针对 LLM 幻觉这一安全领域问答的核心痛点, 构建**生成约束 → 结构化引用 → 可视化核验 → 自动校验**的四层可信链:

1. **生成约束**: 系统提示"仅依据片段回答 + 必须 [n] 引用 + 无依据明确拒答"三原则;
2. **结构化引用**: 回答 `[n]` 与 sources 数组下标一一对应, 契约化(`{answer, sources[{documentName, page, content, score}], retrievalTime, generationTime}`);
3. **可视化核验**: 前端引用可展开显示原文片段、来源文档、页码、相似度百分比, 用户可"查证"而非"盲信";
4. **自动校验**: 评估模块以正则提取引用编号并判定越界(伪造引用检测), 引用编号有效率成为可量化指标——将"可信"从口号变为可测量的数字(注意: 该指标验证编号指向真实来源, 不验证语义支持)。

## 创新点 3: LLM_ONLY vs RAG 的可控对照实验平台

不满足于定性论述 RAG 优势, 而是内建**实验基础设施**, 使论文结论可复现、可审计:

1. **同源双通道**: `rag_chat` 与 `llm_only_chat` 共用同一 LLM/同一提示风格, 唯一差异是是否注入检索上下文——严格的单一变量对照;
2. **参数扫描**: Top-K {1,3,5,10} 与 ChunkSize {256,512,1024} 一键成组实验, 全局 rag_config + 请求级覆盖双层参数体系保证组内一致;
3. **自动 + 人工双轨指标**: 检索侧(Hit/P@K/R@K)、生成侧(关键词命中/引用编号有效率/幻觉判定)、系统侧(检索/生成耗时/token)自动计算; 人工评分(相关性/准确性/完整性 1-5 分 + 幻觉标注)独立存储、可事后补充;
4. **数据可导出**: 逐题结果 CSV 导出(含 BOM 兼容 Excel), 直接支撑论文统计分析;
5. **过程可信**: 逐题真实调用、失败留痕计入 failed, 系统层面杜绝伪造实验数据的可能。

## 创新点 4: 面向真实部署的安全工程实践(系统自身的安全性)

作为"网络安全"课题, 系统自身按安全开发生命周期(SDL)构建, 本身即是安全实践的展示:

| 维度 | 实践 |
|------|------|
| 认证 | BCrypt 慢哈希 + JWT(密钥环境变量、≥32 字节、固定算法防混淆) |
| 授权 | 拦截器统一鉴权 + @RequireAdmin 功能级守卫(防 BFLA) + 数据按 userId 隔离(防 BOLA) |
| 输入 | 上传白名单/大小限制/UUID 随机名/规范化路径前缀校验(防穿越); @Valid 统一参数校验 |
| 注入 | MyBatis-Plus 全参数化, 零字符串拼接 SQL |
| 密钥 | LLM/Embedding Key 仅环境变量; 日志 SensitiveFilter 脱敏; /api/config 无密钥字段; 前端零密钥 |
| 内部通信 | X-Internal-Token 服务间令牌; 内部端口仅绑定 127.0.0.1(compose 配置) |
| 容器 | 多阶段构建、非 root 运行、健康检查、密钥经 env_file 注入不写镜像 |
| 测试 | 15 项安全需求逐项验证(07 篇清单) |

## 可扩展方向(未纳入本期实现, 作为展望)

- 查询改写: 多轮指代消解的 LLM 改写(当前为规则预处理);
- 混合检索: BM25 关键词召回 + 向量召回融合;
- 重排序已实现为可选组件(CrossEncoder bge-reranker-base), 论文中作为消融实验呈现;
- 知识库级 ACL 与检索权限水印。

## 小结

四个创新点构成闭环: **知识工程**(构建可信语料)→ **可信生成**(回答与来源绑定)→ **实验平台**(量化验证 RAG 增益)→ **安全实践**(系统自身满足安全基线)。系统全部功能均已在代码中落地并通过测试(后端 39 项、RAG 服务 77 项), 实验数据由真实运行产出。
