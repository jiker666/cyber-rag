# 05 系统模块设计

> 对应代码: `backend/src/main/java/com/cyberrag/`(10 Controller / 8 Service)、`frontend/src/`。

## 1. 后端模块

### 1.1 通用层

- `common/result/Result<T>`: 统一响应 `{code, message, data}`, code=0 成功;
- `common/exception`: `BusinessException(code, message)` + `GlobalExceptionHandler`(业务异常/参数校验异常/兜底 500, 不泄露堆栈);
- `common/constants/Constants`: 状态常量(文档状态机、角色等)。

### 1.2 安全与鉴权

| 组件 | 职责 |
|------|------|
| `security/JwtUtil` | 签发/解析 HS256 JWT; 密钥长度强制 ≥32 字节(不满足启动即失败), 异常统一 401 |
| `security/AuthContext` | ThreadLocal 保存当前用户(id/username/role), 请求结束清理 |
| `security/RequireAdmin` | 方法级注解, 标记管理员接口 |
| `config/AuthInterceptor` | 拦截 `/api/**`(白名单: 登录/注册), 解析 Token → 查用户 → 注入 AuthContext → 校验 @RequireAdmin |
| `config/PasswordConfig` | BCryptPasswordEncoder(强度 10) |

鉴权链路: 前端 `Authorization: Bearer <jwt>` → 拦截器验签 → ThreadLocal → Controller/Service 取用; 管理接口由注解统一守卫(防 BFLA 式纵向越权); 数据级隔离: 会话/消息按 userId 过滤(防 BOLA 式横向越权)。

### 1.3 业务模块

| 模块 | Controller → Service | 要点 |
|------|---------------------|------|
| 认证 | AuthController → AuthService | 注册(用户名查重+BCrypt)、登录(凭证校验+签发 JWT)、个人信息、改密 |
| 用户管理 | UserController(管理员) | 分页列表、启用/禁用 |
| 知识库 | KnowledgeBaseController | CRUD + 统计同步(文档数/chunk 数) |
| 文档 | DocumentController | 上传(白名单/大小/UUID 随机名/规范化路径校验)→异步入库; 状态轮询接口; 重新入库; 删除(向量→记录→文件) |
| 会话/问答 | ConversationController, ChatController → ChatService | 会话 CRUD; `ask()`: 空问题校验→定位/创建会话→存用户消息→取历史窗口→RagServiceClient.chatQuery→存助手消息(sources JSON)+qa_record |
| 统计 | StatsController → StatsService | 概览卡片 + 7 日趋势 + 分类占比 + 知识库调用排行(SQL 聚合) |
| RAG 配置 | RagConfigController(管理员) | 读写单行 rag_config; 运行时信息透传(不含密钥) |
| 评估 | EvaluationController → EvaluationService | 数据集/题目 CRUD; 任务创建(异步执行); 结果分页; 人工评分提交; CSV 导出; 任务对比 |
| 反馈 | FeedbackController | 对回答打分评论 |

### 1.4 集成层

`integration/RagServiceClient`: RestTemplate + `DefaultUriBuilderFactory(NONE)`(避免中文/特殊字符二次编码), 每个请求注入 `X-Internal-Token`; JSON→DTO 经 `JsonUtil.convert(TypeReference)`(泛型安全, 避免 LinkedHashMap 强转)。

### 1.5 异步与状态机

- 文档入库线程池 `doc-ingest`、评估线程池 `eval-runner`(有界队列, 与 Web 线程隔离);
- 文档状态机: `PENDING →(提交)PARSING →(解析分块完成)EMBEDDING →(向量化入库)COMPLETED`; 任一步异常 → `FAILED` + `error_message`(前端可见, 可"重新入库"重试);
- 评估任务: `PENDING → RUNNING → COMPLETED/FAILED`, 单题失败记录 error 后继续, 不中断批次。

## 2. 前端模块(frontend/src)

### 2.1 基础设施

- `api/request.ts`: axios 实例, 拦截器注入 Token; 响应统一解包 `Result`(code!==0 抛错); 401 清会话跳登录;
- `stores/user.ts`: Pinia 用户状态(localStorage 持久化 token/用户信息, 登出清理);
- `router/index.ts`: 登录/注册公开, 其余路由守卫; `meta.admin` 标记管理员路由(侧边栏按角色显隐);
- `styles/index.css`: 网络安全主题暗色变量(`--bg-base:#0b0f1a`、`--accent:#38bdf8`)。

### 2.2 页面模块

| 页面 | 要点 |
|------|------|
| LoginView / RegisterView | 表单校验 + 演示账号提示 |
| DashboardView | 6 张 StatCard + ECharts 折线(7日趋势)/饼图(分类)/柱状(知识库调用) |
| KnowledgeListView / KnowledgeDetailView | 知识库 CRUD(创建对话框)、统计刷新 |
| DocumentsView | 拖拽上传 + el-progress 进度 + 3s 轮询状态(处理中→完成/失败含原因); 支持重新入库/删除 |
| ChatView | 三栏布局: 左侧会话列表 / 中间消息流 / 右侧参数(Top-K/Temperature)+快捷问题; 打字指示器; 引用 `[n]` 渲染; `SourceList` 折叠面板(文档名/页码/相似度%/原文); 重新生成 / 清空会话 |
| ConversationsView | 历史会话管理 |
| SettingsRagView | RAG 参数表单(管理员) + 运行时只读信息 |
| EvaluationView | 发起任务(模式/数据集/Top-K{1,3,5,10}/ChunkSize{256,512,1024})、任务列表、结果抽屉(自动指标+逐题)、人工评分对话框(el-rate 1-5 + 幻觉开关)、任务对比、CSV 导出(带 BOM, Excel 中文无乱码) |
| ProfileView / UserManageView | 个人信息 / 用户管理(管理员) |

### 2.3 复用组件

- `StatCard`: 图标+数值+标签统计卡(icon 支持 string|Component);
- `ChartView`: ECharts 封装(暗色主题、resize 自适应、卸载清理);
- `SourceList`: 引用来源折叠列表(相似度百分比、页码)。

## 3. RAG 服务模块

见 04 篇; 模块划分为 `core(config/logging/errors)`、`embedding`、`llm`、`vectorstore`、`document`、`rag`、`evaluation`、`api`。API 面:

| 端点 | 功能 | 鉴权 |
|------|------|------|
| GET /health | 存活探针 | 公开 |
| POST /api/ingest/file | 文件入库(解析→清洗→分块→向量化) | 内部令牌 |
| POST /api/ingest/text | 文本入库 | 内部令牌 |
| DELETE /api/ingest/document/{kb}/{doc} | 删除文档向量 | 内部令牌 |
| DELETE /api/ingest/collection/{kb} | 删除知识库集合 | 内部令牌 |
| GET /api/ingest/stats/{kb} | 分块/文档统计 | 内部令牌 |
| POST /api/chat/query | RAG 问答 | 内部令牌 |
| POST /api/chat/llm-only | 对照组问答 | 内部令牌 |
| POST /api/retrieval/search | 检索调试 | 内部令牌 |
| GET /api/config | 运行时信息(无密钥) | 内部令牌 |
| POST /api/evaluation/batch | 批量评测 | 内部令牌 |

## 4. 模块间时序(问答主链路)

```
前端 ChatView ──POST /api/chat/ask──▶ ChatController
   ChatService: 会话定位 → 存用户消息 → 取历史
   ChatService ──RagServiceClient(X-Internal-Token)──▶ rag-service /api/chat/query
        RagPipeline: preprocess → embed → Chroma TopK → (rerank) → context → LLM
   ◀── {answer, sources[], retrievalTime, generationTime}
   ChatService: 存助手消息(sources) + qa_record → AskVO
前端: 渲染回答 + SourceList 引用展开
```
