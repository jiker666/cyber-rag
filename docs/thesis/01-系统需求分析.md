# 01 系统需求分析

> 本文档基于项目实际实现编写, 代码位于 `backend/`(Spring Boot)、`rag-service/`(FastAPI)、`frontend/`(Vue3)。

## 1. 项目背景与目标

大语言模型(LLM)在通用问答中表现出色, 但直接应用于网络安全知识领域存在三个突出问题:

1. **幻觉问题**: 模型可能编造不存在的漏洞编号、错误的防御方案, 在安全领域危害尤甚——错误的修复建议可能导致系统暴露于风险之中;
2. **知识时效性**: 模型训练数据存在截止日期, 无法覆盖最新的 CVE 漏洞与安全实践;
3. **不可溯源**: 生成内容无法给出出处, 专业用户难以验证答案可信度。

本课题设计并实现**基于 RAG(检索增强生成)的网络安全知识智能问答系统**, 以"先检索、后生成、带引用"的方式, 将 LLM 的生成能力锚定在受控的网络安全知识库之上, 实现**答案有依据、来源可追溯、幻觉可度量**的领域问答, 并通过 LLM_ONLY 与 RAG_LLM 对照实验定量验证 RAG 的增益。

## 2. 用户角色分析

| 角色 | 来源 | 核心诉求 |
|------|------|----------|
| 管理员(ADMIN) | role 表 id=1 | 管理用户账号、知识库、文档全生命周期、RAG 参数、评估任务; 查看运营统计 |
| 普通用户(USER) | role 表 id=2 | 选择知识库提问, 查看带引用来源的回答, 管理个人会话, 对回答进行反馈与人工评分 |
| 系统(内部) | Java 后端 ↔ Python RAG 服务 | 通过 `X-Internal-Token` 内部令牌通信, 完成向量化入库与问答编排 |

## 3. 功能需求

### 3.1 用户系统
- 注册/登录(用户名 + 密码), 密码 BCrypt 加盐哈希存储;
- JWT 无状态认证, 有效期可配置(默认 24h);
- 个人信息查看与密码修改;
- 管理员可查看用户列表、启用/禁用账号。

### 3.2 知识库管理(管理员)
- 创建/编辑/删除知识库(名称、描述、分类、封面色);
- 查看知识库统计(文档数、分块数);
- 每个知识库对应 Chroma 中一个独立集合(`kb_{id}`), 实现检索隔离。

### 3.3 文档管理(管理员)
- 支持 PDF / TXT / MD / DOCX 四类文档上传;
- 上传安全: 扩展名白名单、文件大小限制(默认 20MB)、随机文件名存储、防目录穿越;
- 异步处理流水线, 状态机流转 `PENDING → PARSING → EMBEDDING → COMPLETED / FAILED`, 失败记录错误信息;
- 支持重新入库与删除(同步清理向量)。

### 3.4 RAG 智能问答(所有用户)
- 多轮会话管理(创建/切换/清空/删除);
- 问答流程: 查询预处理 → 向量检索 Top-K → (可选)重排序 → 上下文构造 → LLM 生成 → 回答 + 引用;
- 回答以 `[1][2]` 标注引用, 引用来源(文档名、页码、相似度、原文片段)可展开验证;
- 支持重新生成、快捷提问;
- 可调参数: Top-K、Temperature。

### 3.5 运营统计(管理员)
- 概览卡片: 用户数、知识库数、文档数、问答数、反馈数、今日问答;
- ECharts 图表: 近 7 天问答趋势(折线)、知识库分类占比(饼图)、知识库调用排行(柱状)。

### 3.6 RAG 参数配置(管理员)
- 分块大小 ChunkSize(默认 512)、重叠 Overlap(默认 100)、Top-K(默认 5)、Temperature(默认 0.3)、相似度阈值(默认 0.3)、重排序开关与候选数、历史窗口;
- 只读运行时信息: Embedding 模型、LLM 模型(不暴露任何密钥)。

### 3.7 评估实验(管理员)
- 评测数据集管理(题目、参考答案、期望关键词、期望来源文档、类别);
- 对照实验: `LLM_ONLY`(无检索直接生成) vs `RAG_LLM`(检索增强生成);
- 参数实验: Top-K ∈ {1,3,5,10}、ChunkSize ∈ {256,512,1024};
- 自动指标: Retrieval Hit Rate、Precision@K、Recall@K、关键词命中率、引用准确率、平均检索/生成耗时;
- 人工评分: 回答相关性/准确性/完整性(1-5 分)、是否幻觉(是/否);
- 结果明细查看、任务间对比、CSV 导出。

## 4. 非功能需求

| 类别 | 需求 | 实现要点 |
|------|------|----------|
| 安全 | 密码安全 | BCryptPasswordEncoder(强度 10) |
| 安全 | 认证鉴权 | JWT 拦截器 + @RequireAdmin 管理员注解 + AuthContext ThreadLocal |
| 安全 | 密钥管理 | LLM/Embedding API Key 仅经环境变量注入; 日志 SensitiveFilter 脱敏; 前端零密钥 |
| 安全 | 上传防护 | 白名单 + 大小限制 + UUID 随机名 + 规范化路径前缀校验 |
| 安全 | SQL 注入 | MyBatis-Plus 全程参数化(LambdaQueryWrapper) |
| 安全 | 内部通信 | X-Internal-Token 令牌校验, /api/* 全覆盖 |
| 性能 | 异步处理 | 文档入库与评估任务使用专用线程池, 不阻塞请求 |
| 性能 | 检索延迟 | HNSW 近似最近邻, 单次检索毫秒级 |
| 可用性 | 故障隔离 | 单题评估失败不中断批次; 文档处理失败记录原因 |
| 可维护性 | 分层架构 | Controller-Service-Mapper 三层; RAG 服务模块化(provider 抽象) |
| 可测试性 | 全链路测试 | 后端 34 项单测(H2); RAG 服务 53 项测试(Fake Embedding/LLM + 临时 Chroma) |

## 5. 约束与边界

- LLM 仅通过 OpenAI-Compatible 接口接入, 由 `LLM_BASE_URL / LLM_API_KEY / LLM_MODEL` 环境变量配置, 系统不绑定任何厂商;
- 知识内容限定为防御性安全知识(漏洞原理、防御方案、安全编码、法律法规), 不收集、不生成针对真实目标的攻击数据;
- 不引入消息队列、注册中心、微服务网关等超出课题规模的基础设施;
- 评估数据由系统真实运行产生, 禁止伪造实验数据。
