# 06 检索策略设计

> 本文档与系统真实实现对应: 向量检索为默认策略, 混合检索(BM25+RRF)与 CrossEncoder 重排为可选增强, 均可通过配置/请求参数开关。

## 1. 设计动机

网络安全知识问答存在两类典型查询:

1. **语义型**: "如何防止用户输入被拼进 SQL 语句" —— 同义改写多, 依赖向量语义召回;
2. **精确标识型**: "CWE-918"、"CVE-2021-44228"、"BOLA" —— 词面即语义, 向量模型对这类
   罕见 token 的嵌入区分度不足, 纯向量检索容易召回相邻主题(CWE-89)而漏掉目标。

因此检索层采用 **向量检索为基线, 混合检索与重排为可选增强** 的渐进设计,
所有增强默认关闭, 效果由真实实验(Experiment D/E)验证。

## 2. 三级检索架构

```
用户问题
  ↓ 预处理(去控制字符/压缩空白/截断 2000)
  ↓ Query Embedding (BAAI/bge-small-zh-v1.5)
  ├─ 策略 = vector  ──────────────→ Chroma 余弦检索(每知识库一个 Collection)
  ├─ 策略 = hybrid ─→ 向量检索 + BM25 检索 → RRF 融合
  ↓ 相似度阈值过滤(默认 0.3, 向量侧; 低于阈值视为"知识库未覆盖")
  ↓ 可选 CrossEncoder 重排(bge-reranker-base, 候选池 ×4 → 保留 topN)
  ↓ Top-K 截断
检索结果(含 document_id/chunk_index/page/score 等元数据)
```

## 3. 关键实现

### 3.1 向量检索(基线)

- Chroma `PersistentClient`, 每个知识库独立 Collection(`kb_{id}`), cosine 度量;
- Embedding 由外部 Provider 计算(显式传入, 保证模型可切换);
- 多知识库检索结果按余弦相似度归并排序。

### 3.2 混合检索(向量 + BM25 + RRF)

- **BM25 索引**: 按知识库懒构建并缓存, 集合条目数变化自动失效重建;
- **分词**: ASCII 词元(保留连字符, `CWE-918` 为单一词元) + CJK 二元组, 无外部分词依赖;
- **RRF 融合**: `score(d) = Σ_i 1/(k + rank_i(d))`, k=60;
  向量侧候选先过相似度阈值再参与融合, 保持"低相关拒答"语义;
- 仅 BM25 命中的候选无余弦分(`score=null`), 前端显示"关键词命中"标记。

### 3.3 CrossEncoder 重排

- 模型: `BAAI/bge-reranker-base`(懒加载, 未启用时零开销);
- 流程: 向量召回扩大至 `4×K` → 交叉编码器逐对打分 → 保留 topN(默认 3);
- 与混合检索可叠加: 融合排序后的候选同样可进入重排。

## 4. 参数与开关

| 参数 | 位置 | 默认 | 说明 |
|---|---|---|---|
| 检索策略 retrievalStrategy | rag_config 表 / 请求参数 | vector | vector / hybrid |
| Top-K | rag_config / 请求参数 | 5 | 最终返回片段数 |
| 相似度阈值 scoreThreshold | rag_config / 请求参数 | 0.3 | 向量侧过滤 |
| 启用重排 enableReranker | rag_config / 请求参数 | 0 | 1 启用 |
| 重排保留数 rerankTopN | rag_config / 请求参数 | 3 | 重排后保留数量(评测路径未单独设置时取 Top-K, 保证对照实验变量唯一) |

管理员可在「RAG 配置」页修改全局默认; 评测任务可按任务覆盖(记录于 evaluation_task 表),
支撑 Experiment D/E 的对照实验。

## 5. 效果验证方式

见 `06-实验设计.md`(第二轮更新) Experiment D / E:
同一数据集、同一知识库、同一 LLM 与温度, 仅切换检索策略/重排开关,
对比 Hit@K / Precision@K / Recall@K / MRR / 关键词覆盖率 / 响应时间。
