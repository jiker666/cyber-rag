# 07 测试方案

> 实际执行结果(2026-09-18 终版): 后端 **39/39 通过**(H2 + Mockito, JDK 21); RAG 服务 **77/77 通过**(离线 Fake 栈); 前端 `vue-tsc + vite build` 类型检查与构建通过。

## 1. 测试策略总览

| 层 | 工具 | 范围 | 运行方式 |
|----|------|------|---------|
| 后端单元/集成测试 | JUnit5 + Mockito + H2(MySQL 模式) + Awaitility | 服务层、鉴权、API 全链路(集成层 Mock) | `cd backend && mvn test` |
| RAG 服务测试 | pytest + FastAPI TestClient + FakeEmbedding/FakeLLM + 临时目录 Chroma | 清洗/分块/解析/检索/管道/指标/API | `cd rag-service && .venv/bin/python -m pytest` |
| 前端 | vue-tsc 类型检查 + vite 构建 | 全量类型与构建 | `cd frontend && npm run build` |
| 端到端验收 | 手工/脚本 | 完整业务流 | 见第 5 节 |

### 1.1 后端测试要点(`backend/src/test`)

- **环境**: H2 内存库 `MODE=MySQL`, 独立 `schema-h2.sql`/`data-h2.sql`(角色/账号/知识库/rag_config/评测题);
- **Mock 边界**: `@MockitoBean RagServiceClient` —— 业务逻辑真实跑库, 只有跨服务调用被替换, 保证鉴权/状态机/持久化被真实验证;
- **异步断言**: Awaitility 轮询等待文档异步处理完成后再断言状态流转;
- 覆盖: 登录注册(密码错误/重复注册)、JWT 签发解析(过期/篡改/密钥长度)、知识库 CRUD、文档上传(类型白名单/超大文件 413/随机文件名/路径穿越防护)、问答(空问题/历史拼装/来源 JSON 反序列化)、评估(任务执行/人工评分/CSV)、鉴权 API(无 Token 401/普通用户访问管理接口 403)、参数配置(检索策略持久化 vector/hybrid、非法值 400)、健康检查(/api/health 免鉴权返回 UP)。

### 1.2 RAG 服务测试要点(`app/tests`)

- **离线 Fake 栈**:
  - `FakeEmbedding`: 字符级 md5 哈希词袋向量(64 维, 归一化)——共享字符越多余弦越近, 使"检索相关性"在无真实模型下也可断言;
  - `FakeLLM`: 上下文含知识库片段时返回带 `[1]` 引用的固定回答, 支撑引用链路断言;
  - `memory_store`: `chromadb.PersistentClient(tmp_path)`, 真实读写、自动清理;
  - autouse 夹具强制替换 Embedding/LLM 工厂单例, **保证任何测试路径都不会加载真实模型**(防慢测试与意外网络下载);
- 覆盖(77 项):
  - `test_cleaner`: 控制字符/NFKC/装饰线/页码行/空白压缩;
  - `test_chunker`: 尺寸上限、重叠、页码保留、全局编号、非法参数(ValueError);
  - `test_parser`: 扩展名白名单拒绝、大小限制、路径穿越文件名归一、txt 编码回退;
  - `test_retriever`: 多知识库检索、Top-K 截断、阈值过滤、相似度计算;
  - `test_pipeline`: RAG 全链路(引用出现/来源透传/耗时字段)、LLM_ONLY(无来源)、历史窗口、空问题异常;
  - `test_metrics`: 关键词命中率(大小写/空白鲁棒)、Hit/P@K(边界: 0 返回/不足 K/恰为 K/多条相关片段, 分母固定为 K)/R@K、引用编号有效率(有效/越界/无引用/部分有效)、伪造引用、批次聚合;
  - `test_api`: health、文本入库→问答→统计→删除闭环、文件上传(恶意扩展 422/正常 txt)、检索调试、批量评测(含 LLM_ONLY 组检索类指标记 NULL 的口径回归)、参数校验 422 格式、**内部令牌校验(无 Token 401)**、/api/config 不泄露密钥;
  - `test_embedding_factory`: local/openai/openai-compatible 三种 provider 分派与本地模型延迟加载。

## 2. 安全测试清单(对应安全需求逐项验证)

| 安全需求 | 验证方式 | 结果 |
|----------|---------|------|
| 密码 BCrypt | 库中存储为 `$2a$10$...`; 单测验证 encode/matches | ✅ |
| JWT 密钥不硬编码 | 密钥来自 `APP_JWT_SECRET` 环境变量, ≥32 字节启动校验 | ✅ |
| 上传类型限制 | `.jsp` 上传返回 422(白名单外) | ✅ |
| 上传大小限制 | 超过 MAX_FILE_SIZE_MB 拒绝 | ✅ |
| 随机文件名 | 存储名 UUID.hex, 原名仅展示 | ✅ |
| 防目录穿越 | `../../etc/passwd.txt` 归一化后拒绝/改名存储 | ✅ |
| SQL 参数化 | 全程 MyBatis-Plus Wrapper/#{} 占位 | ✅(代码审查) |
| 接口鉴权 | 无 Token 访问受保护接口 401 | ✅ |
| 管理员权限 | 普通用户访问管理接口 403(@RequireAdmin) | ✅ |
| API Key 仅环境变量 | 无任何代码/配置硬编码; .env 不入库(.gitignore) | ✅ |
| 日志不打印密钥 | SensitiveFilter 对 sk-*/Bearer/api_key 打码; /api/config 无密钥字段 | ✅(单测断言) |
| 前端不存密钥 | 前端仅存 JWT; 无任何 API Key 字段 | ✅ |
| 后端参数校验 | @Valid + 全局异常处理 → 统一 422 响应格式 | ✅ |
| 统一异常处理 | GlobalExceptionHandler 兜底, 不泄露堆栈 | ✅ |
| 内部服务令牌 | rag-service /api/* 校验 X-Internal-Token | ✅ |

## 3. 性能观测点

系统在以下位置记录真实耗时与用量, 支撑性能分析(不伪造):

## 5. 端到端验收流程(部署后人工执行)

```
1. docker compose up -d(或 scripts/run-local.sh)
2. 浏览器打开前端 → admin/admin123 登录
3. 知识库管理 → 新建知识库"测试库"
4. 文档管理 → 上传 dataset/ 下若干 .md/.txt/.pdf
   → 观察状态 PENDING→PARSING→EMBEDDING→COMPLETED(轮询刷新)
   → 故意上传 .jsp 验证被拒绝
5. 退出 → user/user123 登录 → 智能问答
   → 选择知识库提问"如何防御 SQL 注入?"
   → 验证回答带 [1] 引用、可展开来源(文档名/页码/相似度/原文)
   → 追问"那 XSS 呢?"(多轮)→ 重新生成 → 清空会话
6. admin 登录 → 数据看板: 卡片数字与 7 日趋势图变化
7. 参数设置: 修改 Top-K=3 → 问答生效
8. 评估实验: 选数据集 → 分别跑 LLM_ONLY 与 RAG_LLM
   → 查看逐题结果与汇总 → 提交人工评分 → 任务对比 → 导出 CSV
9. 用户管理: 禁用 user 账号 → 该账号登录被拒
```
