# 向量数据库与 Embedding 技术解析

## Embedding: 语义的数学表示

Embedding 模型将文本映射为高维稠密向量(如 384/768/1024 维), 语义相近的文本在向量空间中距离更近:

- "如何防止 SQL 注入" 与 "SQL 注入的防御措施" → 向量高度相似
- "如何防止 SQL 注入" 与 "今天天气如何" → 相似度低

### 相似度度量

- **余弦相似度**: 衡量方向夹角, 对文本长度不敏感, 最常用
- **欧氏距离**: 空间直线距离
- **内积**: 未归一化时同时受方向与模长影响

多数场景先将向量 L2 归一化, 此时余弦相似度与欧氏距离单调等价。

### 中文 Embedding 模型

BGE 系列(如 bge-m3、bge-large-zh)在中文检索任务上表现优秀; M3E、text2vec 等亦常用。选型关注: 维度(影响存储与速度)、最大输入长度、检索精度(MTEB/C-MTEB 榜单)。

## 向量数据库的核心功能

以 Chroma、Milvus、Qdrant、FAISS 为例, 核心能力:

1. **向量索引**: HNSW(分层可导航小世界图)是主流近似最近邻(ANN)算法, 高召回低延迟
2. **元数据过滤**: 检索时按 metadata 条件过滤(如 knowledge_base_id = 3)
3. **增删改**: 按 ID 或按过滤条件删除, 支持知识库重建
4. **持久化**: 数据落盘与加载

### HNSW 简要原理

构建多层图: 上层稀疏(长边, 快速跳跃)、底层稠密(短边, 精确逼近)。查询从顶层入口贪心下降, 底层局部搜索得到近邻。以少量召回损失换取亚线性查询速度。

## 分块与检索的工程权衡

1. **chunk 粒度**: 小块检索准但上下文碎, 大块上下文全但引入噪声 —— 需结合评估实验选择
2. **overlap**: 相邻块重叠(如 10%-20%)缓解边界语义割裂
3. **混合检索**: 向量(语义) + BM25(关键词) + 重排序的组合显著提升效果
4. **元数据设计**: 文档 ID、页码、块序号支撑引用溯源

## 典型检索流程

```python
query_emb = embedding_model.embed_query("如何防 CSRF?")   # 查询向量化
results = collection.query(
    query_embeddings=[query_emb],
    n_results=5,
    where={"knowledge_base_id": 3},     # 权限/范围过滤
)
# 相似度: Chroma 返回距离, score = 1 - distance (余弦距离时)
```

## 安全考量

1. **多租户隔离**: 按知识库分集合/分区, 服务端强制过滤, 防越权检索
2. **提示注入**: 入库内容可能含恶意指令, 参见大模型应用安全指南
3. **数据投毒**: 知识库入库需审核流程与来源可信控制
