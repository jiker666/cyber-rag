# 威胁建模方法 STRIDE 实践

## 什么是威胁建模

在设计阶段系统化地回答四个问题:

1. 我们在构建什么?(架构与数据流)
2. 哪里会出问题?(威胁识别)
3. 我们打算怎么办?(缓解措施)
4. 做得好不好?(验证与迭代)

"在设计图上找漏洞"的成本远低于"在生产环境里找漏洞"。

## STRIDE 六类威胁

| 首字母 | 威胁 | 违反属性 | 典型例子 |
|--------|------|---------|---------|
| S | 仿冒 | 认证 | 凭证填充、会话劫持 |
| T | 篡改 | 完整性 | 参数篡改、SQL 注入改数据 |
| R | 抵赖 | 不可否认性 | 操作无日志, 用户否认行为 |
| I | 信息泄露 | 机密性 | 日志打印密码、错误信息泄露堆栈 |
| D | 拒绝服务 | 可用性 | 慢速攻击、超大文件耗尽资源 |
| E | 权限提升 | 授权 | 越权访问(横向/纵向)、注入 RCE |

## 实践步骤

### 1. 画数据流图(DFD)

元素: 进程、数据存储、数据流、外部实体、信任边界。

以一个问答系统为例:

```
[用户] →(Token+问题)→ [API 网关] ⇄ [认证服务]
                          │
                          ├⇄ [问答服务] →(查询)→ [向量库]
                          │        └→(上下文)→ [LLM 服务]
                          └⇄ [MySQL]
```

### 2. 标记信任边界

跨边界的数据流是威胁高发区: 外网→DMZ、应用→数据库、本系统→第三方 LLM。

### 3. 逐元素套用 STRIDE 提问

对每条数据流问: 谁能仿冒发送方? 数据流可被篡改吗? 泄露了什么? ……

示例(问答服务 ↔ LLM 服务):

- I: 提问内容经第三方 LLM, 是否含敏感数据 → 脱敏策略/私有化部署
- T: LLM 返回内容被直接渲染 → 输出编码; 被直接执行 → 禁止
- E: LLM 服务凭据泄露 → 环境变量+最小权限+轮换

### 4. 定级与缓解

用风险矩阵(可能性 × 影响)排序, 为每个高优威胁设计缓解并纳入 backlog。

### 5. 迭代

架构变更(新增第三方组件、新接口)时重新建模, 威胁模型与代码同版本演进。

## 落地技巧

- 从关键业务流程与敏感数据出发, 不追求一次覆盖全部
- 团队工作坊形式(开发+安全+测试)效果好于单人闭门
- 输出物纳入代码评审检查清单, 让模型"活"在流程里
- 常见陷阱: 只建模不缓解、模型写完即过时、忽略内部威胁
