# 渗透测试方法论与报告撰写

## 渗透测试流程(PTES)

1. **前期交互**: 明确范围、目标、规则(ROE)、授权书、时间窗口
2. **情报收集**: 被动(OSINT、子域名、历史泄露)与主动(端口、服务、指纹)
3. **威胁建模**: 结合业务识别高价值攻击路径
4. **漏洞分析**: 手工验证 + 自动化扫描交叉确认, 剔除误报
5. **漏洞利用**: 仅在授权范围内验证可利用性, 最小影响原则
6. **后渗透**: 权限提升、横向移动评估(按约定, 通常点到为止)
7. **报告**: 风险定级、复现步骤、修复建议、复测确认

## 信息收集要点

- 子域与资产: 证书透明度日志、DNS 记录
- 端口与服务: Nmap 版本探测(仅授权资产)
- Web 指纹: 框架、服务器、WAF、前端技术栈
- 公开信息: GitHub 泄露密钥、历史漏洞报告、招聘信息透露的技术栈

## 常用测试维度

- 认证: 弱口令、爆破、会话管理缺陷
- 授权: 水平/垂直越权(重点! 自动化难覆盖)
- 输入处理: 注入类(SQL/XSS/命令/SSRF/反序列化)
- 业务逻辑: 支付篡改、验证码绕过、流程跳过
- 配置: 默认凭证、调试端点、目录列表、备份文件

## 报告结构

```
1. 概述(测试范围、方法、时间、授权)
2. 风险统计(按等级统计漏洞数量)
3. 高危/中危/低危漏洞明细:
   - 漏洞名称与等级(CVSS)
   - 影响资产与描述
   - 复现步骤(请求/响应证据, 敏感信息脱敏)
   - 危害分析
   - 修复建议(具体可执行)
4. 加固建议汇总与复测计划
```

## 报告写作规范

- 客观准确: 只写经验证的事实, 不夸大危害
- 可复现: 步骤完整, 附证据截图/Payload(脱敏)
- 建议可落地: 给出具体代码或配置示例, 而非"加强安全"式空话
- 定级合理: 结合 CVSS 与业务影响, 避免等级通胀

## 职业道德红线

- 严格在授权范围与时间窗口内工作
- 不扩大利用、不破坏数据、不留后门
- 发现超预期高危风险立即按约定上报
- 报告与数据保密, 项目结束后按约定销毁
