# 数据脱敏与加密技术应用

## 数据分类分级

实施保护前先分类分级, 区分处理成本:

| 级别 | 示例 | 保护要求 |
|------|------|----------|
| 核心数据 | 密钥、生物特征 | 硬件保护、专库隔离、强审计 |
| 重要数据 | 身份证号、手机号、银行卡 | 加密存储、严格访问控制 |
| 一般数据 | 用户昵称、行为日志 | 访问控制、按需脱敏 |
| 公开数据 | 公告、帮助文档 | 完整性与可用性保护 |

## 脱敏技术

按展示场景选择脱敏算法:

- **掩码**: `138****5678`、`张*` —— 适合前端展示
- **截断**: 只保留前缀
- **替换/泛化**: 身份证出生日期替换为年龄段
- **哈希**: 保留可关联性不可逆推, 适合关联分析
- **格式保留加密(FPE)**: 密文保持原格式, 兼容旧系统校验

注意: 脱敏应发生在数据出口(接口层/日志层), 内部计算可使用原文, 但需权限管控。

## 传输加密

- 全站 TLS 1.2+, 证书自动轮换
- 敏感字段(如登录密码)即使在内网也建议应用层二次加密
- 禁止降级: 关闭 SSLv3/TLS1.0, 启用 HSTS

## 存储加密

- **密码**: BCrypt/Argon2 慢哈希, 不可逆
- **可逆加密**: AES-256-GCM, 密钥由 KMS 管理, 禁止硬编码
- **数据库层**: 字段加密或透明加密(TDE), 配合最小权限账号
- **备份**: 同等加密强度, 异地存放, 访问独立审计

## 日志脱敏实践

```java
// 日志过滤器/切面对敏感字段统一处理
public static String maskPhone(String phone) {
    if (phone == null || phone.length() != 11) return "***";
    return phone.substring(0, 3) + "****" + phone.substring(7);
}
// 结构化日志标记敏感字段, 输出前统一掩码
log.info("user={} phone={}", userId, maskPhone(phone));
```

常见必须脱敏的日志字段: 密码、Token、API Key、身份证号、银行卡号、手机号、地址。

## 密钥管理生命周期

生成(强随机) → 存储(KMS/HSM) → 使用(内存中解密, 用后清理) → 轮换(定期+事件触发) → 销毁(可验证销毁)。任何环节泄露都视为安全事件, 需立即轮换并审计影响范围。
