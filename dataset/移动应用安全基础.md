# 移动应用安全基础

## 移动端特有攻击面

相比 Web, 移动应用运行在用户可控设备上, 客户端代码与本地数据更易被分析:

1. **逆向分析**: 反编译 APK/IPA 提取代码、密钥、接口逻辑
2. **本地存储泄露**: 明文存 Token/敏感信息到 SharedPreferences/plist/SQLite
3. **不安全的传输**: 部分流量走 HTTP、证书校验缺失或禁用
4. **IPC 暴露**: Android 四大组件导出未鉴权, 被其他应用调用
5. **WebView 桥接**: JS Bridge 暴露敏感原生能力
6. **重打包**: 修改客户端植入恶意逻辑再分发

## 客户端防逆向(提高成本, 不能依赖)

- 代码混淆: Android(ProGuard/R8)、iOS(符号剥离)
- 加固: 壳保护、VMP, 增加动态调试成本
- 完整性校验: 签名校验 + 服务端下发校验值, 防重打包
- 反调试/模拟器检测(注意对抗升级, 仅作辅助)

核心原则: **客户端的任何"秘密"都会被提取**, 敏感逻辑与密钥必须在服务端。

## 本地数据安全

```
Android: EncryptedSharedPreferences / Keystore 密钥加密敏感项
iOS: Keychain(SecItem) 存 Token, kSecAttrAccessible 属性控制解锁条件
```

- 禁止日志输出 Token/个人信息(注意 release 构建关闭 debug 日志)
- 退出登录彻底清理本地缓存
- 剪贴板不自动读取敏感内容

## 传输安全

- 全量 HTTPS + 证书锁定(Certificate Pinning)对抗中间人与抓包调试
- 但注意: 锁定密钥轮换机制, 避免 CA 变更导致全员断连
- 网关统一鉴权, 端上 token 短有效期 + 静默续期

## 与后端配合的安全设计

1. **接口签名**: 请求加时间戳+nonce+HMAC 签名, 防抓包重放
2. **设备指纹**: 关联设备与账号, 异常设备触发二次验证
3. **风控接口**: 注册/登录/支付等关键接口做行为风控(频率、轨迹)
4. **服务端权威**: 会员等级、余额、权益判断一律服务端, 客户端仅展示

## 发布安全

- 签名密钥妥善保管(硬件/托管), 不入库
- 应用商店分发 + 校验机制, 警惕第三方市场重打包版本
- 崩溃/性能 SDK 评估数据采集合规性(隐私政策披露)
- 定期依赖组件漏洞扫描
