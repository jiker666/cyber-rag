# 路径穿越与命令注入防御指南

## 路径穿越

### 原理

路径穿越(CWE-22)利用 `../` 序列逃逸受限目录, 读取或覆盖任意文件:

```
GET /download?file=../../../../etc/passwd
```

若服务端直接拼接路径: `baseDir + "/" + file`, 即可读到系统敏感文件。编码变形(`%2e%2e%2f`、`..%c0%af`)与绝对路径注入是常见绕过手法。

### 防御

1. **规范化后校验前缀**(核心):

```java
Path base = Paths.get(uploadRoot).normalize().toAbsolutePath();
Path target = base.resolve(userInput).normalize().toAbsolutePath();
if (!target.startsWith(base)) {
    throw new BusinessException("非法路径");
}
```

2. 文件名使用 `Path.getFileName()` 或直接由服务端生成随机名, 不接受用户提供的路径
3. 白名单校验文件名字符集(仅字母数字与少量安全符号)
4. 运行账号遵循最小权限, 限制可访问目录
5. Web 服务器层拒绝包含 `..` 的请求(多层防御)

## 命令注入

### 原理

命令注入(CWE-78)发生在将用户输入拼接进操作系统命令时, 攻击者用分隔符追加任意命令:

```java
// 危险: 拼接执行
Runtime.getRuntime().exec("ping -c 1 " + host);
// 输入: 8.8.8.8; cat /etc/passwd
```

常见分隔符: `;`、`&&`、`||`、`` ` ``、`$(...)`、换行。除 shell 外, 还需警惕 SQL、LDAP、XML、模板注入等同族注入。

### 防御

1. **避免调用系统命令**, 优先使用语言内置库完成同等功能(如 Java `InetAddress.isReachable()` 代替 ping)
2. 确需执行命令时, **不经过 shell 拼接**, 使用参数数组形式并校验每个参数:

```java
ProcessBuilder pb = new ProcessBuilder("ping", "-c", "1", host);
// host 先经白名单校验(域名/IP 正则)
```

3. 输入白名单校验(IP 正则、枚举值), 拒绝元字符
4. 最小权限运行命令进程, 设置超时与输出上限

## 通用原则

两类漏洞的共同根因是"用户输入被拼接进解释型上下文"。通用防御范式:

1. 优先使用无需拼接的安全 API(参数化)
2. 无法参数化时做严格白名单校验
3. 失败即拒绝, 不做"过滤黑名单"式的修补
4. 纵深防御: 最小权限、隔离运行环境、监控告警
