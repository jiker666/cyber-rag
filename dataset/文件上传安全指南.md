# 文件上传安全防御指南

## 文件上传的风险

文件上传功能是 Web 攻击的高发入口, 主要风险包括:

1. **WebShell 上传**: 上传可执行脚本(如 `shell.jsp`、`shell.php`), 直接获得服务器控制权。
2. **目录穿越**: 利用 `../../` 将文件写到任意路径, 覆盖关键配置。
3. **存储型 XSS**: 上传含脚本的 HTML/SVG 文件并被浏览器直接渲染。
4. **拒绝服务**: 上传超大文件或畸形压缩包耗尽磁盘与内存。
5. **恶意文件分发**: 服务器被当作恶意文件中转站。

## 防御措施

### 1. 严格校验文件类型(白名单)

- 校验扩展名白名单(如仅允许 pdf、txt、md、docx), 拒绝一切可执行扩展名
- 校验文件头(Magic Number), 防止仅改扩展名绕过; 但注意伪造文件头风险, 白名单 + 头校验需配合
- 使用成熟解析库读取内容, 拒绝解析失败或内容异常的文件

### 2. 重命名存储

使用服务端生成的随机文件名(如 UUID)存储, 保留原始文件名仅作为展示元数据, 彻底消除特殊文件名、路径穿越与解析漏洞:

```java
String ext = FilenameUtils.getExtension(originalName).toLowerCase();
if (!ALLOWED_EXTENSIONS.contains(ext)) {
    throw new BusinessException("不支持的文件类型");
}
Path target = uploadRoot.resolve(UUID.randomUUID() + "." + ext);
// 二次确认: 规范化后必须仍位于上传根目录内
if (!target.normalize().startsWith(uploadRoot)) {
    throw new BusinessException("非法文件路径");
}
```

### 3. 限制文件大小

- 应用层限制单文件大小(如 50MB)
- Web 服务器层限制请求体大小(nginx `client_max_body_size`)
- 上传频率与配额限制, 防止滥用

### 4. 隔离存储

- 上传目录不赋予执行权限
- 静态资源单独域名/CDN 提供, 与应用域隔离
- 下载时设置 `Content-Disposition: attachment` 与正确的 `Content-Type`

### 5. 内容检测

对文档进行病毒扫描, 对图片重新编码(消解隐写与内嵌脚本), 对 PDF/Office 文档解析失败即拒绝。

## 与 RAG 系统的结合

在知识库问答系统中, 上传的文档会经过"解析 → 清洗 → 分块 → 向量化"流水线。上传入口必须:

1. 白名单限制为可解析的文档类型(PDF/TXT/MD/DOCX)
2. 解析失败标记文档状态为 FAILED 并记录原因, 不中断服务
3. 文件内容仅用于向量化检索, 原文件不直接暴露下载 URL(需要时经鉴权接口返回)
