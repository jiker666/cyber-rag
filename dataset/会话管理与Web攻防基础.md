# 会话管理与 Web 攻防基础

## 会话机制

HTTP 无状态, 应用通过会话标识(Session ID / Token)关联请求与用户。会话生命周期: 创建(登录) → 传递(Cookie 或 Header) → 校验(每次请求) → 销毁(登出/过期)。

## 会话安全要点

1. **会话固定攻击**: 登录前后使用同一会话 ID, 攻击者可预先植入; 防御: 认证成功后立即重置/更换会话标识。
2. **会话劫持**: 窃取他人会话凭证冒充身份; 防御: 全站 HTTPS + HttpOnly + Secure Cookie, 防范 XSS。
3. **过期策略**: 空闲超时与绝对超时结合; 敏感操作后刷新会话; 注销时服务端真正失效凭证而非仅前端删除。
4. **并发控制**: 关键账号异地登录告警、可强制单点登录。

## 常见 Web 攻击速查

| 攻击 | 根因 | 一句话防御 |
|------|------|-----------|
| SQL 注入 | 输入拼接进 SQL | 参数化查询 |
| XSS | 输出未编码执行 | 输出编码 + CSP |
| CSRF | 请求无来源校验 | CSRF Token + SameSite |
| SSRF | 服务端请求用户 URL | 白名单 + 协议限制 |
| 点击劫持 | 页面被嵌套 | X-Frame-Options/frame-ancestors |
| 越权(BOLA/BFLA) | 缺对象/功能级授权 | 服务端逐请求校验 |
| 文件上传 | 类型未校验 | 白名单 + 随机名 + 大小限制 |
| 开放重定向 | 跳转 URL 用户可控 | 白名单域名 |

## 安全开发生命周期(SDL)

1. 需求阶段: 安全需求与合规分析
2. 设计阶段: 威胁建模(STRIDE: 仿冒/篡改/抵赖/信息泄露/拒绝服务/权限提升)
3. 开发阶段: 安全编码规范、静态扫描(SAST)
4. 测试阶段: DAST、渗透测试、SCA 依赖扫描
5. 发布阶段: 安全评审与基线检查
6. 运维阶段: 监控、漏洞响应、补丁管理

## 日志与取证基础

- 保留完整请求日志(时间、来源 IP、账号、动作、结果), 但不记录密码与 Token 明文
- 异常检测关注: 高频失败登录、横向扫描、异常 User-Agent、大量 404/403
- 取证顺序: 易失性数据(内存、连接) → 磁盘镜像 → 日志关联分析
