# DES 与分组密码工作模式(教学示例)

本文用于演示经典对称密码的工作模式与已知风险, 帮助理解"为什么不使用 ECB、为什么 DES 被淘汰"。

## DES 概述

DES(Data Encryption Standard)是 1977 年发布的分组密码, 分组长度 64 位, 密钥有效长度 56 位。由于密钥过短, 1998 年 EFF 的 Deep Crack 机器数日内即可穷举破解, DES 已被 NIST 撤销标准, 实践中被 AES 取代。

## 工作模式

### ECB(电码本模式)

每个分组独立加密, 相同明文分组得到相同密文分组:

- 优点: 实现简单, 可并行
- 致命缺陷: 泄露明文模式(经典"企鹅图"实验), 且分组可被替换重排
- 结论: 永远不要用 ECB 加密超过一个分组的数据

### CBC(密码分组链接)

加密前先与上一密文分组异或, 首个分组与初始化向量(IV)异或:

- IV 必须随机且不可预测, 且每次加密都不同
- 填充预言攻击风险: 解密失败与填充失败若返回可区分错误, 可逐字节恢复明文, 应统一错误响应并使用"Encrypt-then-MAC"或 AEAD 模式

### CTR(计数器模式)

将计数器加密生成密钥流与明文异或, 流式加密:

- 可并行, 无填充
- 关键约束: 计数器/nonce 绝不可重用, 否则两段密文异或即消去密钥流

### GCM(Galois/Counter Mode)

CTR 加密 + 认证标签, 同时提供机密性与完整性(AEAD), 是当前推荐模式。

## 安全使用原则

1. 优先选用 AES-256-GCM 等 AEAD 模式
2. 密钥通过 KMS/环境变量管理, 不硬编码
3. IV/nonce 每次随机且唯一, GCM 的 nonce 重用会灾难性泄露认证密钥
4. 认证失败时拒绝解密输出, 不给出失败原因细节
5. 密钥与算法可配置升级(密码敏捷性), 避免永久绑定单一算法

## 演示代码(Python)

```python
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
import os

key = os.urandom(32)                      # 256-bit key
nonce = os.urandom(12)                    # GCM 96-bit nonce, 每次必须随机
enc = Cipher(algorithms.AES(key), modes.GCM(nonce)).encryptor()
ct = enc.update(b"secret data") + enc.finalize()
tag = enc.tag                             # 认证标签
```
