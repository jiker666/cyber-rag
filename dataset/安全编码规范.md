# 安全编码规范与最佳实践

## 通用原则

1. **永不信任输入**: 所有外部数据(HTTP 参数、Header、文件、第三方 API 返回)在进入解释型上下文(SQL、HTML、Shell、XPath、模板)前必须校验或编码。
2. **默认拒绝**: 授权逻辑默认拒绝, 逐条显式放行; 前端隐藏按钮不是权限控制。
3. **最小权限**: 进程、数据库账号、云 IAM 均只授予必需权限。
4. **失败安全**: 异常时进入安全状态(拒绝服务请求而非跳过校验), 错误信息不泄露内部细节。
5. **纵深防御**: 校验分层进行, 单层失效不致整体失守。

## 输入与输出

- 优先白名单校验(类型、长度、范围、格式、字符集)
- SQL: 参数化查询/ORM 占位符, 拼接一律禁止
- HTML: 输出上下文编码, 富文本走白名单净化库
- 命令: 避免拼接, 必要时参数数组 + 白名单
- 文件: 类型白名单、大小限制、随机名、规范化后校验路径前缀

## 认证与授权

- 密码: BCrypt/Argon2 自适应加盐哈希
- 会话: 短有效期、登出失效、防 CSRF(SameSite/Token)
- 接口: 服务端逐对象校验归属(BOLA)、逐功能校验角色(BFLA)
- 敏感操作: 二次认证

## 密钥与配置管理

- 密钥/API Key 仅经环境变量或 KMS 注入, 严禁入库、入代码、入日志
- 日志脱敏: 密码、Token、密钥、身份证号等字段过滤或掩码
- 生产配置与开发配置隔离, 生产关闭调试与文档端点

## 日志与审计

- 记录: 认证成败、授权拒绝、关键业务操作、异常输入
- 日志结构化并集中收集, 保证可追溯
- 不记录敏感明文, 防日志注入(过滤换行与控制字符)

## 依赖与供应链

- 维护依赖清单(SBOM), 使用 SCA 工具扫描已知漏洞
- 锁定版本, 升级走评审; 关注重大 CVE(如 Log4j2、Fastjson 历史漏洞)
- 构建链路最小权限, 制品签名校验

## 代码评审安全检查清单

- [ ] 新接口是否做了认证与授权(BOLA/BFLA)
- [ ] SQL/HTML/命令拼接是否存在
- [ ] 文件上传校验是否完整
- [ ] 敏感数据是否明文(存储/传输/日志)
- [ ] 错误信息是否泄露内部实现
- [ ] 依赖是否引入已知漏洞版本
- [ ] 关键操作是否有审计日志
