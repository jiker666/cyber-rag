# 云安全与容器安全基础

## 云安全责任共担模型

- **IaaS**: 云厂商负责物理与虚拟化层安全, 用户负责 OS、应用、数据
- **PaaS**: 云厂商延伸到运行时, 用户负责应用代码与配置
- **SaaS**: 云厂商负责大部分, 用户负责账号与数据治理

核心思想: 安全责任随控制权下移而上移, 用户永远对自己的数据与访问控制负责。

## 常见云配置风险(CIS 基准)

1. 对象存储桶公开读写, 导致数据泄露
2. IAM 密钥长期有效、权限过宽, 甚至硬编码进代码
3. 安全组对 0.0.0.0/0 开放高危端口(22/3389/数据库)
4. 元数据服务无防护, 被 SSRF 获取实例凭证
5. 未开启操作审计日志

防御: 按 CIS Benchmark 加固、最小权限 IAM、定期配置审计、启用 IMDSv2、密钥轮换。

## 容器安全要点

### 镜像层

- 使用精简可信基础镜像, 固定版本 tag
- 镜像扫描(CVE 检测)进入 CI 流水线, 高危不合规即阻断
- 不在镜像中打包密钥与敏感配置, 使用构建参数注入并清理中间产物

### 运行时

- 最小权限: 非 root 用户运行、只读文件系统、capabilities 裁剪
- 资源限制: CPU/内存 limit, 防止资源耗尽
- 禁用 privileged 与不必要挂载(docker.sock 泄露等于宿主机 root)
- 网络默认拒绝, 按需放行

### 编排层

- 镜像仓库使用 HTTPS 并签名校验
- 敏感信息存于 Secret, 权限最小化
- 审计 API Server 访问, 控制面板端口不暴露公网

## Dockerfile 安全示例

```dockerfile
FROM python:3.11-slim@sha256:<digest>    # 固定 digest
RUN addgroup --system app && adduser --system --ingroup app app
USER app                                   # 非 root
COPY --chown=app:app . /app
```

- [ ] 镜像扫描通过, 无高危 CVE
- [ ] 非 root 运行, 资源限制配置
- [ ] 敏感配置来自 Secret/环境变量注入
- [ ] 网络策略最小化
- [ ] 日志与监控已接入
