# RAG 检索增强生成技术概念解析

## 什么是 RAG

RAG(Retrieval-Augmented Generation, 检索增强生成)通过"先检索、后生成"的两阶段架构增强大语言模型: 用户提问后, 系统先从外部知识库检索相关内容, 再将其作为上下文交给 LLM 生成回答。它缓解了 LLM 的三大缺陷: 知识截止、幻觉、私域知识缺失。

## 典型流程

### 离线索引阶段

1. **文档解析**: 提取 PDF/TXT/MD/DOCX 的文本内容
2. **清洗**: 去除控制字符、页眉页脚、乱码等噪声
3. **分块**: 按语义边界与固定长度切分为 chunk, 通常 256-1024 字符, 相邻块保留重叠以保持语义连贯
4. **向量化**: 使用 Embedding 模型将每个 chunk 映射为稠密向量
5. **入库**: 向量与原文、元数据(文档名、页码、块序号)一同存入向量数据库

### 在线问答阶段

1. **查询预处理**: 去噪、关键信息抽取、多轮对话改写
2. **查询向量化**: 同一 Embedding 模型编码用户问题
3. **检索**: 向量数据库按余弦相似度返回 Top-K 最相关 chunk
4. **重排序**: 可选, 用 CrossEncoder 对召回结果精排, 提升相关性
5. **上下文构建**: 将 chunk 编号拼接进提示词
6. **生成**: LLM 依据上下文回答, 并按要求以 [1][2] 标注引用来源
7. **溯源**: 回答与来源 chunk(文档、页码、相似度)绑定返回

## 关键参数

| 参数 | 作用 | 典型值 |
|------|------|--------|
| Chunk Size | 分块长度, 过小语义破碎, 过大噪声多 | 256-1024 |
| Overlap | 相邻块重叠, 保持上下文连贯 | 50-200 |
| Top-K | 检索返回条数, 影响召回与噪声平衡 | 3-10 |
| Score Threshold | 相似度阈值, 过滤低相关结果 | 0.3-0.5 |
| Temperature | 生成随机性, 事实性问答宜低 | 0.1-0.7 |

## 核心价值: 消除幻觉与可溯源

1. **依据事实生成**: Prompt 中明确要求"仅依据提供的知识库内容回答, 找不到依据需如实说明"
2. **引用绑定**: 回答中 [n] 与来源列表一一对应, 用户可展开验证
3. **知识可更新**: 更新文档并重建索引即可, 无需重训模型
4. **权限可控**: 检索限定在授权知识库范围内, 实现数据边界控制

## 与微调(Fine-tuning)的对比

| 维度 | RAG | 微调 |
|------|-----|------|
| 知识更新 | 实时, 换文档即可 | 需重新训练 |
| 可溯源性 | 强, 可给出出处 | 弱 |
| 幻觉抑制 | 显著 | 有改善但不保证 |
| 成本 | 部署检索组件 | 训练算力与数据标注 |
| 适用场景 | 知识问答、动态知识库 | 风格、格式、领域语言习惯 |

## 常见评估指标

- 检索质量: Hit Rate、Precision@K、Recall@K、MRR
- 生成质量: 回答准确性、引用准确性、幻觉率
- 系统指标: 检索耗时、生成耗时、端到端延迟

## 典型风险与对策

1. **检索失败导致答非所问**: 调整分块与 Top-K, 增加重排序
2. **知识库噪声**: 入库前清洗, 设置相似度阈值
3. **提示注入**: 文档内容可能包含恶意指令, 需对入库内容做隔离标记
4. **多轮指代**: 结合会话历史改写查询
