# 数据库安全加固实践

## 攻击面概览

数据库是攻击者的最终目标(数据资产所在地), 常见风险: SQL 注入、弱口令、权限过大、公网暴露、明文存储、备份泄露、审计缺失。

## 分层加固清单

### 网络层

- 禁止数据库端口(3306/5432/1433/27017)直接暴露公网
- 应用与数据库同私网, 安全组仅放行应用网段
- 管理访问走跳板机/VPN, 可选 SSL 加密连接

### 账号与权限

1. **一应用一账号**, 按schema最小授权:

```sql
CREATE USER 'cyberrag_app'@'10.0.%' IDENTIFIED BY '强随机密码';
GRANT SELECT, INSERT, UPDATE, DELETE ON cyber_rag.* TO 'cyberrag_app'@'10.0.%';
-- 不授予 DROP/ALTER/GRANT/SUPER/FILE
```

2. 禁止 root/sa 做应用连接账号; 禁止 % 全网段授权
3. 密码策略: 长随机密码、定期轮换、密码管理器托管
4. 删除测试/默认账号(mysql 库示例账号、空密码账号)

### SQL 注入防护

应用侧参数化是根本(见 SQL 注入防护指南), 数据库侧纵深防御:

- 最小权限使 `UNION SELECT` 即使成功也读不到敏感表
- Web 应用不使用 FILE 权限(防 `LOAD_FILE`/`INTO OUTFILE` 读写文件)
- 错误信息不回传到前端

### 数据保护

- 敏感字段加密(AES-GCM, 密钥在应用/KMS 而非数据库)
- 密码用 BCrypt, 永不明文
- 生产数据导出需审批, 导出数据脱敏

### 审计与监控

- 开启审计日志或 binlog: 谁在什么时间执行了什么
- 告警规则: 全表扫描、异常大结果集、深夜 DDL、新增账号/授权语句
- 慢查询日志兼顾性能与异常发现

### 备份与恢复

- 3-2-1 备份(含异地), 备份同样加密与权限管控
- **定期恢复演练** —— 未验证的备份等于没有
- 防勒索: 备份系统与生产网络隔离

## MySQL 快速自检

```sql
-- 空密码/异常账号
SELECT user, host FROM mysql.user WHERE authentication_string='';
-- 过大权限账号
SELECT user, host FROM mysql.user WHERE Super_priv='Y' OR File_priv='Y';
-- 近期授权变更(审计开启时)
```
