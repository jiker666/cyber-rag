# 安全日志审计与入侵检测

## 日志是安全的基石

没有日志, 攻击无从发现、事件无法溯源。安全日志体系需要覆盖: 认证事件、授权决策、数据访问、配置变更、系统与网络事件。

## 关键日志源

1. **应用日志**: 登录成功/失败、权限拒绝、关键业务操作、异常输入
2. **Web 服务器**: 访问日志(IP、URL、状态码、UA、响应大小)
3. **系统日志**: auth.log/Security 事件、进程创建、计划任务
4. **数据库**: 慢查询、全表扫描、异常账号操作
5. **网络设备/防火墙**: 连接记录、阻断记录
6. **终端 EDR**: 进程树、文件操作、注册表修改

## 入侵检测指标(IOC)分析

发现攻击的关键在于识别异常模式:

- 短时间内大量 401/403: 口令爆破
- 单 IP 高频扫描多种路径: Web 扫描器
- 单账号异地/多 IP 同时登录: 凭证泄露
- 大量出站连接到同一外部 IP: 数据外传/反向 Shell
- 深夜新增管理员账号、异常计划任务: 权限维持
- User-Agent 出现 sqlmap/nmap/nuclei 等工具特征: 自动化攻击

## SIEM 与关联分析

- 集中收集(Normalize) → 关联规则(多源事件串联) → 告警分级 → 响应处置
- 典型规则: 同一 IP 5 分钟内失败登录 >20 次 且 成功登录 1 次 → 疑似爆破成功
- 衰减告警噪音: 聚合、抑制、动态阈值

## 日志安全自身要求

- **防篡改**: 追加写入、远程转发(WORM/签名), 攻击者第一件事常是清日志
- **脱敏**: 不记录密码明文、完整 Token、API Key、身份证号
- **保留周期**: 等保要求日志留存不少于 6 个月
- **时钟同步**: NTP 统一时间, 否则多源日志无法对齐
- **性能**: 异步采集, 日志系统故障不得拖垮业务

## 检测工程实践

1. 从真实攻击场景出发写检测规则(ATT&CK 技战术映射)
2. 规则上线前用攻击复现流量验证, 定期红蓝对抗检验
3. 告警闭环: 每条告警有处置人与处置记录
4. 指标化运营: MTTD(平均检测时间)、MTTR(平均响应时间)
