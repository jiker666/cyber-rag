# 密码学中的哈希函数与消息认证码

## 哈希函数

将任意长度输入映射为固定长度摘要, 具备:

1. **确定性**: 相同输入永远相同输出
2. **单向性**: 无法由摘要反推输入
3. **抗碰撞性**: 难以找到两个不同输入产生相同摘要
4. **雪崩效应**: 输入微小变化, 输出剧烈变化

## 常见哈希算法

| 算法 | 摘要长度 | 现状 |
|------|---------|------|
| MD5 | 128bit | 已破解(碰撞), 禁用于安全场景 |
| SHA-1 | 160bit | 已有实际碰撞攻击, 禁用 |
| SHA-256/SHA-3 | 256bit | 当前推荐 |
| SM3 | 256bit | 国密标准 |

## 哈希的正确用途

1. **完整性校验**: 文件分发附带 SHA-256, 下载方比对
2. **密码存储**: 必须使用 BCrypt/Argon2/PBKDF2 等慢哈希加盐(普通 SHA-256 太快, 易被 GPU 暴力枚举)
3. **数据指纹**: 去重、索引(注意彩虹表风险, 关键场景加盐)

## HMAC(基于哈希的消息认证码)

哈希只能证明"内容没变", HMAC 还能证明"发送者持有密钥":

```
HMAC_SHA256(key, message) → 32 字节认证码
```

典型应用:

1. **API 签名**: 客户端用密钥对请求参数签名, 服务端同样计算并比对, 防篡改+防伪造
2. **Webhook 验签**: 第三方回调带 HMAC 签名, 接收方验证后再处理, 防伪造回调
3. **Token/PBKDF2 内部构造**

```python
import hmac, hashlib

def sign(secret: bytes, payload: str) -> str:
    return hmac.new(secret, payload.encode(), hashlib.sha256).hexdigest()

# 校验: 使用恒定时间比较, 防时序攻击
received = "..."  # 请求头带来的签名
ok = hmac.compare_digest(sign(secret, payload), received)
```

## 常见误用

1. **无盐哈希存密码**: `md5(password)` → 彩虹表秒查
2. **HMAC 比较用 `==`**: 短路比较泄露时序信息, 应使用恒定时间比较
3. **密钥复用**: 不同用途使用不同密钥派生(KDF 分离)
4. **自造加密**: 不要发明自己的密码学协议, 使用标准库与成熟方案
5. **用哈希做完整性又当认证**: 公开哈希任何人都能算, 认证必须 HMAC 或签名

## 数字签名与 HMAC 的区别

- HMAC: 对称密钥, 双方共享密钥, 计算快, 适合服务间/客户端与服务端
- 数字签名(RSA/ECDSA): 私钥签名公钥验证, 可第三方证明, 适合公开可验证场景(证书、软件签名)
