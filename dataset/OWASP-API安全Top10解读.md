# OWASP API Security Top 10 解读

OWASP API Security Top 10 针对现代 API(REST/GraphQL)特有的攻击面总结十大风险, 是 API 安全设计与评审的核心参考。

## API1: BOLA(对象级授权失效)

Broken Object Level Authorization, API 最常见的漏洞。服务端仅校验用户已登录, 未校验其是否有权访问该资源对象, 导致越权:

```
GET /api/orders/1001   # 用户A的订单
GET /api/orders/1002   # 直接访问用户B的订单, 若无归属校验即越权
```

防御: 每次访问资源时校验资源归属( WHERE user_id = currentUserId ), 使用全局唯一不可预测的 ID(UUID)作为额外防线。

## API2: 认证失效

API 认证机制复杂(JWT、OAuth、API Key、MFA), 任何一环薄弱都会被利用。常见问题: 弱凭证、无速率限制的爆破、Token 未过期/未撤销、明文传输。防御: 统一认证网关、强密码策略、登录限流、短周期 Token 与刷新机制、MFA。

## API3: BFLA(功能级授权失效)

Broken Function Level Authorization。普通用户可调用管理接口, 如普通用户请求 `POST /api/admin/users/delete`。防御: 服务端逐接口做角色校验(注解/拦截器), 默认拒绝; 管理路由独立分组并加额外网关校验; 不信任前端隐藏按钮。

## API4: 资源无限消耗

API 未限制请求频率、数据量与计算资源, 易被滥用或 DoS。防御: 速率限制(令牌桶)、分页强制上限、响应体裁剪、超时与并发上限、按配额计费。

## API5: 功能级授权失效(旧版)

在 2023 版中拆分并入 BFLA 与 BOLA 相关条目, 关注管理功能接口暴露问题。

## API6: 敏感业务流暴露

自动化脚本滥用业务流程, 如批量抢购、薅羊毛、验证码轰炸。防御: 人机验证、设备指纹、业务速率限制、风控规则。

## API7: SSRF

服务端根据用户输入发起请求, 详见 SSRF 防御指南: 白名单目标、禁用危险协议、解析后校验 IP、网络隔离。

## API8: 安全配置错误

默认配置、调试接口暴露、CORS 配置为 `*`、目录列表开启、不必要的 HTTP 方法。防御: 配置基线化与自动化检查(如 CI 中扫描)、生产环境关闭 Swagger/Actuator 敏感端点、CORS 精确白名单。

## API9: 库存管理失效(Inventory Management)

废弃 API、影子 API、测试接口未纳入管理, 成为攻击盲区。防御: API 资产清单、网关统一接入、版本生命周期管理。

## API10: 不安全的 API 使用(2023 新增)

消费第三方 API 时信任其返回数据、未校验集成回调, 导致注入与逻辑漏洞。防御: 对外部数据一视同仁地校验与编码、回调验签。

## 工程落地建议

1. 网关统一鉴权、限流、审计日志
2. 授权遵循"默认拒绝"原则, 逐对象、逐功能校验
3. 输入输出校验永不信任任何一方数据
4. 将 API 安全测试纳入 CI/CD
