# 网络分区与防火墙策略设计

## 网络分区的基本思想

将网络按信任级别与业务功能划分为多个区域, 区域间设置访问控制点, 实现:

1. **限制横向移动**: 单点失陷不等于全网失陷
2. **收敛攻击面**: 每个区域只暴露必需的服务
3. **审计可视化**: 跨区流量都经过策略点, 便于监控

## 经典分区模型(以 Web 应用为例)

```
Internet
   │ (仅 80/443)
[DMZ 区]  反向代理 / WAF
   │ (仅到应用端口)
[应用区]  Web 应用 / API 服务
   │ (仅数据库端口)
[数据区]  MySQL / 向量库 / 对象存储
   │
[管理区]  CI/CD、监控、跳板机(独立准入)
```

## 策略设计原则

1. **默认拒绝**: 白名单放行, 未明确允许的一律拒绝
2. **最小化规则**: 精确到源地址+端口, 禁止 0.0.0.0/0 → any 的大开口
3. **双向最小化**: 应用→数据库只开 3306, 数据库不主动外联(防数据外传与反向 Shell)
4. **管理面隔离**: SSH/RDP/数据库管理端口不对公网暴露, 经 VPN/跳板机访问
5. **出入分离**: 允许入站 ≠ 允许出站, 应用服务器出站仅限白名单(依赖的 API、更新源)

## 主机防火墙示例

```bash
# 应用服务器: 仅放行 8080(经反代) 与管理网 SSH
iptables -P INPUT DROP
iptables -A INPUT -i lo -j ACCEPT
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -A INPUT -p tcp --dport 8080 -s 10.0.1.0/24 -j ACCEPT   # 仅 DMZ 网段
iptables -A INPUT -p tcp --dport 22   -s 10.0.9.0/24 -j ACCEPT   # 仅管理网段
iptables -P OUTPUT DROP
iptables -A OUTPUT -p tcp --dport 443 -d api.partner.example -j ACCEPT
iptables -A OUTPUT -p udp --dport 53  -j ACCEPT                   # DNS
```

## 云环境下的对应物

- **安全组**: 实例级状态防火墙, 同样按最小白名单配置
- **网络 ACL**: 子网级无状态过滤, 作为第二道防线
- **微分段**: 按工作负载身份(而非 IP)的策略, 适配云内东西向流量

## 常见错误配置

- 安全组 0.0.0.0/0 放开 22/3389/3306/6379 → 全网爆破/勒索温床
- "临时调试"的放行规则永久化 → 变更管理需回收流程
- 数据库服务器可自由出站 → 数据外泄通道
- 各区域之间大片互通, 分区形同虚设

## 验证与运维

- 定期策略审计(规则命中率分析, 清理僵尸规则)
- 端口扫描自查(仅对自有资产)
- 变更走流程并留痕, 策略备份与回滚
